# 名将記録 v0.1.5

信長の野望・真戦の個人用「名将ガチャ」記録ツールです。
静的HTML / CSS / JavaScriptだけで動きます。ビルド・サーバー構築・外部AI APIは不要です。

## 最初に

**詳しい操作手順は `docs/SETUP.html` をダブルクリックして開いてください。**
（アプリの `index.html` は、ダブルクリックではなくGitHub Pages等のHTTP(S)から開きます。）

1. ZIPを展開します。
2. 中身をアプリ公開用のGitHubリポジトリへ配置します。`index.html` がリポジトリ直下になるようにします。
3. Settings → Pages → Deploy from a branch → main / (root) → Save。
4. 記録用に、別の **Private** リポジトリを作成します。READMEを追加してmainブランチを用意します。
5. 記録用リポジトリだけを選択したFine-grained tokenを作り、ContentsをRead and writeにします。
6. アプリの歯車 → データ同期 / GitHub設定で接続します。
7. 最初のシーズン名と初期排出プールを設定します。初期97武将の高排出／低排出区分は登録済みです。
8. スマホも同じアプリURLを開き、同じ記録用リポジトリへ接続して「GitHubの記録を使う」を選びます。

## 添付データについて

- 添付の武将名・所属 **97人** をそのまま収録しています。
- 低排出S 42人を登録済みです。その他の初期武将55人は高排出Sとして登録しています。排出ON/OFFのみ未設定です。
- 初回は現在の名将ガチャに出る武将だけを排出プールでONにしてください。高排出／低排出は必要な場合のみ編集します。
- 五十音順のための「よみ」は補助情報として追加しました。武将編集画面から修正できます。
- 依頼文に登場する島津義久など、添付にいない武将を勝手に追加していません。必要な武将は画面から追加できます。
- 元の一覧は `source/generals-original.tsv`、低排出指定は `source/low-rate-names.txt` に残しています。
- 低排出リストの「妻木煕子」は、既存武将DBの表記「妻木熙子」に対応させています。

## 実装済み

- 「+1」 / 「+5」（Sなし5連） / 「Sが出た」から記録
- S天井30回、高排出S5連続後の低排出S保証
- 日時付きログ、取消履歴を残す連続UNDO
- 所属フィルタ、よみによる五十音順、名前検索、低排出の固定幅色帯
- 武将の追加・編集・排出ON/OFF、排出区分の一括設定
- 武将情報を含む排出プールの不変スナップショット
- シーズン切替、初期DBコピー、過去シーズンの保持
- S履歴、操作ログ、プール履歴、基本集計、平均S間隔
- GitHub Contents API同期、競合検出、再送時の二重登録防止
- JSONエクスポート／復元、S履歴CSV、自動の復元用バックアップ

## 同期の動作

入力は先に端末へ保存して即座に画面へ反映し、GitHub通信を待たずに次の入力ができます。短時間の連続入力は通信をまとめます。起動時・画面復帰時・表示中45秒ごとにも同期します。
**「GitHub同期済み」を確認してから別の端末を使ってください。** 「端末に保存済み」「未同期」「同期中」の時点では、もう一方の端末へ入力しないでください。
通信に失敗しても端末の記録は残り、再同期できます。同時更新は自動で混ぜず、両方を保持して選択画面に進みます。
端末トークンは公開ソースにもエクスポートJSONにも含めません。

## v0.1の範囲

記録開始時のカウンタは0です。シーズン途中から正確に使う場合は、そのシーズンの履歴を順に入力してください。カウンタだけの直接補正・過去日時の手動修正は実装していません。
画面が開いている状態での通信切断は扱えますが、ネット接続なしでの初回起動やPWAオフライン起動は対象外です。
GitHub同期は整形後のJSONが950,000バイト以下まで。上限でも端末保存・JSONエクスポートは可能です。

## v0.1.5 入力の高速化・5連追加（2026-10-11）

- ＋5で「Sが1体も出なかった5連」をワンタップ記録。内部は5回分の個別ガチャ履歴として保存され、天井・総回数も正しく＋5されます。
- 天井が25/30以上なら＋5は押せません。Sを含む5連では実際の排出順に＋1と「Sが出た」を使ってください。
- ＋5の直後に「直近の5連を戻す」を選ぶと、5回分を一括で取り消します。取消履歴は残ります。
- ＋1 / ＋5 / S の入力処理からGitHubへの通信待ちを除去。端末への正常保存完了後に画面を更新し、GitHubへは非同期にまとめて同期します。
- 通信中に新しく入力した分を古いレスポンスで上書きしないよう、ローカルのrevisionとGitHubのSHAを照合し直します。競合時は既存の確認画面で操作します。
- データの `schemaVersion`、保存キー、既存レコード、GitHub接続先は変更していません。v0.1.4で利用中のURLと同じGitHub Pages公開場所へ、ZIP中身を全ファイル上書きで配置してください（`sync-merge.js` は新規追加）。
- ブラウザが古い画面を表示する場合はページを再読み込みしてください。公開ファイルの変更が反映されたことは画面左上の「v0.1.5」で確認できます。

※操作レスポンスは端末保存までの時間となり、実際のGitHubの応答時間そのものは短縮しません。オフライン・API通信失敗時も記録は端末に残ります。別端末に持ち替える前に必ず同期完了を確認してください。
