最初の設定と、毎日の使い方

アプリを置く場所と、記録を保存する場所を分けて準備します。
設定が済んだら、日々の操作は「+1」「+5」「Sが出た」のいずれかです。

01アプリをGitHub Pagesで公開

  1. GitHubの新規リポジトリ画面を開きます。
  2. Repository nameを meisho-gacha にします。
  3. Publicを選択し、READMEを追加して作成します。
  4. 作成したリポジトリで Add file → Upload files を選びます。
  5. ZIPを展開し、中にある index.html と同じ階層のファイル・フォルダ一式をアップロードします。ZIPそのものや、外側の「meisho-gacha-v0.1」フォルダを丸ごと置かないでください。GitHubの一覧の直下に index.html が見えれば正解です。
  6. Commit changes で保存します。
  7. リポジトリ上部の Settings → Pages を開きます。
  8. Sourceを Deploy from a branch、Branchを main、フォルダを /(root) にして Save。
  9. Pages画面に公開URLが表示されたら開きます。通常は https://あなたのユーザー名.github.io/meisho-gacha/ です。

インストールやビルドは不要です。Pagesの反映待ち中は、リポジトリのActionsで進行状況を確認できます。

アプリ自体は公開URLで開けますが、各端末のトークン・あなたの記録はアップロードしたソースに入りません。記録用JSONやトークンを、この公開リポジトリへ置かないでください。

GitHub Freeでは公開リポジトリからPagesを利用できます。詳しくは末尾の公式手順参照。

02記録専用の非公開リポジトリを作る

  1. もう一度新規リポジトリ画面を開きます。
  2. Repository nameを meisho-gacha-data にします。
  3. Private を選びます。
  4. READMEを追加 して作成してください。これで main ブランチができます。

このリポジトリではPagesを設定しません。記録ファイル data/record.json は、アプリの初回接続時に作成されます。

03専用のアクセストークンを作る

  1. GitHub右上の自分のアイコン → Settings。
  2. Developer settings → Personal access tokens → Fine-grained tokens。
  3. Generate new token を選びます。
  4. 名前は meisho-record-PC など、端末を区別できるものにします。
  5. Expirationで期限を選択します。期限が切れたら新しいトークンを作り、アプリ側で差し替えます。
  6. Resource ownerは自分のGitHubアカウント。
  7. Repository accessを Only select repositories にし、meisho-gacha-dataだけ を選びます。
  8. Repository permissionsの Contents → Read and write を設定します。MetadataのReadは自動で付く項目です。それ以外の権限は不要です。
  9. Generate token。表示されたトークンをコピーします。

トークンはアプリの「GitHub設定」に貼り付けます。公開ファイルや記録JSONには書きません。トークン表示画面を閉じると再表示できないため、必要ならパスワード管理ツールへ保存してください。

スマホ用に同じ権限の別トークンを作ると、片方だけを無効化できて管理しやすくなります。

04PCを接続する

  1. 公開したアプリを開きます。
  2. 右上の歯車 → データ同期 / GitHub設定。
  3. 以下を入力します。
項目入力内容
Owner自分のGitHubユーザー名
リポジトリ名meisho-gacha-data
ブランチmain
保存ファイルdata/record.json
アクセストークン先ほどコピーしたトークン
  1. 自分専用のPCなら「この端末にトークンを保存する」をON。
  2. 接続して確認 を押します。
  3. 初回は「記録ファイルを作成しますか？」が出るので、この端末の記録を保存。
  4. メイン画面の GitHub同期済み を確認します。

トークンを保存した場合、このブラウザの保存領域に置かれます。暗号化された保管庫ではありません。同じGitHub Pagesのドメイン上に置く別アプリも、信頼できるものだけにしてください。保存をOFFにした場合は、そのタブのセッション中だけ保持します。

05シーズンと初期プールを用意する

  1. 最初のシーズンを始める を押して、S5 などの名前を確定します。
  2. 初期プール画面で、今、名将ガチャから出る武将だけONにします。
  3. 高排出／低排出は初期97武将に設定済みです。訂正が必要な場合だけ 武将・排出区分を設定する から編集します。
  4. 名前を「シーズン開始時プール」にし、この内容で更新 を押します。

これで記録開始です。新武将の追加は「武将管理 → ＋ 武将を追加」。追加時はOFFなので、解放されたタイミングでONにしてください。

初期一覧にない武将は追加できます。新規追加武将は排出区分を設定するまでプールでONにできません。よみも編集可能です。

v0.1は0回から記録します。すでにガチャを引いたシーズンの途中から使う場合は、そのシーズンの引いた結果を順に入力してください。カウンタだけを直接設定する機能や、過去の日時への書き換えはありません。

06スマホでも同じ記録を使う

  1. PC側で GitHub同期済み になっていることを確認します。
  2. スマホのブラウザで、PCと同じ公開URLを開きます。
  3. 最初の画面で GitHubの記録を読み込む を選びます。スマホ側で新しいシーズンを作る必要はありません。
  4. 手順04と同じOwner・リポジトリ・ブランチ・保存ファイルを入力します。スマホ用のトークンを設定します。
  5. 接続して確認 → GitHubの記録を使う。
  6. シーズン名・回数がPCと同じになれば接続完了です。

別の端末へ持ち替える前に、使っていた側の「GitHub同期済み」を確認してください。新しく使う側も画面を開いて同期が終わるのを待てば、そのまま入力できます。

アプリ本体を更新するときは公開用リポジトリのファイルを更新します。公開URLを変えない限り、端末側の記録はそのままです。

毎日の操作

場面操作
A/BなどS以外+1 を1回。
Sが出なかった5連+5 を1回。5回分が記録されます。天井25/30以上では使えません。
Sが出たSが出た → 所属 → 武将。+1を別途押す必要はありません。
押し間違い直近1件を戻す。直近が＋5なら「直近の5連を戻す」で5回分を一括取消できます。
次が30回目+1を押しても武将選択へ進みます。通常としては保存しません。
高排出5連続「次のSは低排出確定」と表示。通常の+1は使えます。次のSは低排出だけ選べます。
引いたSを選ぶのをやめるキャンセル。1回分も加算されません。

＋5はSが1体も出なかった5連専用です。Sを含む5連は実際の排出順に＋1と「Sが出た」を使ってください。入力は即座に端末保存され、GitHub同期は後から進みます。通信中にも次の入力ができますが、別端末へ移る前は必ず「GitHub同期済み」を確認してください。
記録日時は日本時間で秒まで表示します。「Sが出た」はボタンを押した時刻を使い、武将選択を終えた時に1回分をまとめて保存します。

排出プールが増えたとき

歯車 → 排出プール管理で、新しく解放された武将をONにし、「10/24 プール更新」などの名前で保存します。過去のプールは残り、新しいS記録だけが新しい版に紐づきます。

次のシーズンへ

歯車 → シーズン管理 → シーズンを切り替える → YES → シーズン名を確定 → 初期プールを作成。名前を確定する前ならNOやキャンセルで戻れます。確定後は新シーズンになり、両カウンタが0になります。旧履歴はシーズン管理から閲覧できます。

新シーズンの新武将は、切替後に武将管理で追加します。過去の名前・区分・プールは編集によって書き換わりません。

バックアップと復元

歯車 → バックアップ / エクスポート → 全シーズンをJSONで保存。武将DB・全シーズン・プール履歴・操作ログが1つのファイルに入ります。

復元するには「JSONから復元」でファイルを選び、内容を確認して復元します。復元前の記録もJSONダウンロードと端末内の復元用バックアップに残します。ダウンロードしたファイルが保存されたことも確認してください。

GitHub上の data/record.json のHistoryには更新ごとのコミットが残ります。過去の版のJSONをダウンロードして、アプリから復元できます。

操作ログにUNDO自体も残るため、JSONやGit履歴から記録と取り消しを追えます。アプリ上の集計は取り消された入力を除いて計算します。

困ったとき

「同期に失敗」と出た

記録は先にこの端末へ保存されています。ネット接続を確認して、メイン画面の「同期」を押してください。解消しない場合はJSONを保存しておけば記録を確保できます。失敗した端末の記録が同期されるまでは、もう一方からの入力を控えてください。

401 / 403 / 404が出る

401はトークンの無効・期限切れ、403は権限不足やAPI制限などです。404はOwner・リポジトリ名・ブランチ・トークン対象を確認します。記録用リポジトリはREADME付きで作成し、mainが存在する状態にしてください。トークンはFine-grained / 記録用リポジトリだけ / ContentsのRead and writeが必要です。

「別の端末から更新されています」と出た
  1. 両方の端末で新しい入力を止めます。
  2. メイン画面の「確認する」を開きます。
  3. 両方の記録をまとめて保存し、ファイルの保存を確認してチェックを入れます。
  4. どちらの記録を使うか選びます。自動合流は行いません。
  5. 選ばなかった側だけにある入力は、必要に応じて記録し直してください。

まとめて保存したJSONもインポートできます。「端末側」「GitHub側」のどちらを復元するか選択します。

スマホとPCの回数が合わない

同じOwner・リポジトリ・ブランチ・保存ファイルかを確認してください。片方が未同期なら、まずそちらを同期します。両方に独立した入力がある場合は競合として止まるので、上の手順で確認します。端末の時計がずれても履歴の順番は登録順ですが、表示日時は端末の時計によります。

画面が「読み込んでいます」のまま

index.html をダブルクリックして開いていませんか？アプリはGitHub PagesのURLで開いてください。app.jsなどがindex.htmlと同じ階層にあるか、ブラウザでJavaScriptが有効かも確認します。セットアップ手順のこのHTMLは、ダブルクリックで読めます。

初期プール設定の途中で閉じた

シーズンはすでに作成されています。歯車 → 排出プール管理から続けてください。プールを保存するまではガチャ入力ができないため、未設定の状態で記録が紛れ込むことはありません。

保存容量のエラーが出た

端末保存に失敗した場合、その入力は成功扱いにしません。まず既存記録をJSONで保存してください。v0.1のGitHub同期は整形JSONで950,000バイトまでです。到達した場合はデータ形式の拡張が必要です。履歴を自動削除することはありません。

動作確認について

同梱の自動テストでは、天井境界、低排出保証、SのUNDO、シーズン切替、プールの保存、文字コード、PC/スマホ相当の同期・競合・通信失敗を検証しています。実際のGitHubトークンでの通信・Pages公開・実機ブラウザでの表示操作は、この納品時点では未検証です。

接続後、試しに「+1」を1回入力 → もう片方の端末で「同期」 → 両方で1回増えていることを確認 → 直近1件を戻す → 再同期、の順で確認してください。取消済みのテスト入力は集計には含まれず、操作ログには残ります。
